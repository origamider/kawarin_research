# セッションを締める

ユーザーは飽きやすいので、質問は最小限にし、会話から読み取れることは自分で埋める。

## 1. 今日触った論文を特定
- この会話と `git diff` から、今日読んだ・話した論文（`papers/<slug>.md`）を挙げる

## 2. 各論文を更新（frontmatter）
- **steps**: 終わったステップに `done: true, date: <今日>, note: "<一言>"`。会話で終わったと言っていないものは触らない
- **status**: 初めて触った論文は `reading` に。全ステップ完了なら `done` にしてよいか一言聞く（done にするときは `finished: <今日>` も付ける）
- **read**: 何を学んだかを一言（30字前後）で上書き
- **write**: 会話に出た疑問・仮説・世界モデルへの接続を、配列に1〜2個**追記**（既存は消さない）
- **teach**: 誰かに説明するつもりの3行（`|` のブロック文字列）。`explain-before-shorten` の流れで、口頭で説明できる形にしてから短くする
- **考察**: 会話でユーザーが語った考え・理解・疑問は、本文の `## 考察` に**ユーザー自身の言葉を活かして**残す（言い回しの整理と段落分けまで。主張は変えない・足さない）。書いたら `updated: <今日>`
- 考察の中に事実の誤解がありそうなら、書き換えずに会話で一言指摘し、直すかはユーザーに任せる
- 新しく分かった知見があれば本文 `## Insights` に1行追記
- 会話にない内容をでっち上げない。材料が無い欄は空のままにする

## 3. 次の一手
- 次の未完ステップを1つ示す。ステップが無ければ「次回、分け方を相談しよう」と書くだけにする（勝手に作らない）

## 4. commit / push
- `npm run build` が通ることを確認
- 差分を短く見せ、「この内容で公開していい？」と一度だけ聞く（公開サイトのため）
- OK なら commit-message skill の規約（例: `docs: 📝 PlaNet の3章を読了する`）で commit して push

## 5. 締めの返答
3行以内：今日の成果／次の一歩／ひとことの労い
